# 시나리오 — 2026-05-12 작업분 통합 데모

오늘 구현·검증한 기능을 한 번에 끝까지 따라가는 사용자 시나리오. 발표·재현·QA용.

---

## 0. 등장 인물 & 사전 상태

**페르소나 — 지수(28세, 1인 가구)**
이사 후 방을 새로 꾸미고 싶다. 측정·치수 감각이 없어 가구가 방에 맞을지 막막함.
한국 가구 쇼핑몰을 즐겨 보지만, 사진만으로 “우리 방에 어울릴지” 판단이 어렵다.

**시스템 사전 상태**
- MySQL 가동 (`authentic_db`)
- AI/Backend/Mobile 세 서비스 기동 (포트 8001 / 18080 / 8082)
- Flyway V1 ~ V10 적용 완료, 카탈로그 28건 시드 + 행마다 `/static/furniture/<id>.{jpg,glb}`
- Phase B 자격증명 `application-local.yml` 등록 + 야간 배치 한 번 실행 → Naver 캐시 280건 보유
- 지수 계정 `u_dev`가 users 테이블에 존재

## 1. 메인 시나리오 (Happy Path)

### Step 1 — 홈에서 시작
**Mobile**: 앱 열면 HomeScreen.
**액션**: “방 사진 업로드” 탭.
**결과**: UploadScreen으로 이동.

---

### Step 2 — 거실 사진 업로드
**액션**: 갤러리에서 자기 방 사진(가구 일부 포함) 선택 → “업로드”.
**시스템**
- Mobile `uploadPhoto()` → `POST /api/v1/spaces/photo`, `X-User-Id: u_dev`
- Backend: 검증(MIME, 크기, 해상도), `users.existsById(u_dev)` 통과, 디스크에 저장
  (`src/backend/var/object-storage/spaces/YYYY/MM/DD/<roomId>.jpg`), 새 `Space` row (`status=PENDING_ANALYSIS`)
- 응답: `{roomId, status:"PENDING_ANALYSIS"}`
- Mobile: `roomId`와 로컬 `photoUri`를 nav state로 가지고 **AnalyzingScreen**으로 이동

**관찰자 시선**: 401 / 422 / 5xx 발생 시 401(`UNKNOWN_USER`)이면 users 테이블 시드를, 422(`IMAGE_NOT_FOUND`)이면
Backend↔AI storage root 일치 여부를 점검.

---

### Step 3 — 분석 진행 (실 ML 가동)
**Backend AIOrchestrator** (포커리 또는 폴링 트리거):
1. `Space` 조회 → `PENDING_ANALYSIS`이면 시작
2. 두 가지를 **병렬**로 호출:
   - AI `POST /analyze/space` — YOLO로 가구 ref 잡고 MiDaS depth로 룸 폭/길이 추정 + OpenCV k-means로 mainColor
   - AI `POST /analyze/style` — HSV 히스토그램 + 룰 5종으로 SCANDINAVIAN/MODERN/CLASSIC/SIMPLE/INDUSTRIAL 분류
3. 결과 DB 기록 (`status=ANALYZED`, `dimensions`, `main_color`, `style`)

**AI 첫 호출은 cold**: YOLOv8n (~6 MB) + MiDaS_small (~80 MB) + EfficientNet 백본 (~10 MB) 한 번에 다운로드. ~60초.
warm은 1~2초.

**Mobile AnalyzingScreen**: 폴링(지수 백오프, 60s 예산)으로 `GET /api/v1/spaces/{roomId}` 호출.
`status=ANALYZED`가 되면 StyleSelectionScreen으로 이동, AI 감지 스타일(`SCANDINAVIAN`, 0.64) 전달.

---

### Step 4 — 객체 검출 화면 (오늘 추가한 기능)
**StyleSelectionScreen**에서 “**객체 검출 보기**” 버튼 탭 → **ObjectsScreen**.

**시스템**
- Mobile `getRoomObjects()` → Backend `GET /api/v1/spaces/{roomId}/objects`
- Backend는 소유권(X-User-Id) 검증 후 AI `POST /analyze/objects` 호출 (YOLO 단독, warm ~2초)
- 응답: `objects: [{label, bbox:[x1,y1,x2,y2], confidence}, ...]`, `imageWidth`, `imageHeight`

**화면**: 원본 사진(`photoUri` 로컬) 위에 bbox 오버레이(라벨별 색상) + 리스트
```
chair  74%   [502, 360, 644, 525]
chair  70%   [338, 401, 432, 528]
laptop 65%   [368, 307, 440, 359]
bowl   60%   [549, 262, 585, 286]
...
```
**관찰**: 같은 사진을 ML이 정량적으로 어떻게 “읽었는지” 처음으로 시각 확인.

---

### Step 5 — 스타일 선택
**StyleSelectionScreen** 다시 돌아옴.
- AI 감지: SCANDINAVIAN (64%) — 해당 옵션 옆에 “AI가 감지한 스타일” 배지 표시
- 지수는 그대로 SCANDINAVIAN 유지 또는 다른 스타일 선택 가능 (e.g. MODERN으로 변경)
- “다음” → Backend `PUT /api/v1/spaces/{roomId}/preferred-style` → RecommendationScreen

---

### Step 6 — 가구 추천 + AR (Phase A)
**RecommendationScreen** 진입 시 `getRecommendations()`:
- Backend가 카탈로그 28건을 Python `/recommend/furniture`로 보내 점수화
- Python은 `imageUrl`만 알지만, Backend가 응답 enrich 단계에서 `modelUrl`을 DB lookup으로 주입
- 4개 카테고리(책상/침대/의자/조명) × top-3 = 12장 카드

**각 카드 구성** (오늘 만든 새 레이아웃):
```
+----------------------------------------------+
| [jpg]  Aurora Modern Bed                     |
| 220cm  ₩680,000          매칭 87%            |
| x160   "모던 침대로 SCANDINAVIAN 룸 보완..."|
| x90    [위시리스트에 추가] [AR로 배치]      |
|                                              |
| ─ 비슷한 실제 상품 ────────────────────────  |
| [Naver] [Naver] [Naver] [Naver] (가로 스크롤)|
+----------------------------------------------+
```

**“AR로 배치” 탭** → ARPlacementScreen
- 카드의 `modelUrl=/static/furniture/f_bed_001.glb` 우선 사용
- Mobile은 `apiBaseUrl`을 자동 prefix → `http://localhost:18080/static/furniture/f_bed_001.glb`
- WebView `<model-viewer>`가 GLB 로드, 사용자가 회전/줌/배치
- (현재 GLB는 빈 placeholder — Sketchfab CC0 자산으로 교체하면 즉시 실 가구 표시)

**“비슷한 실제 상품” 가로 스크롤** (Phase B):
- 카드 마운트 시 `getFurnitureSimilar()` → Backend `GET /api/v1/furniture/{id}/similar`
- 캐시(`furniture_similar_cache`) 조회, top-10 Naver 상품 반환
- 가격 + 썸네일 표시, 탭 시 Naver 상세 페이지 외부 브라우저로 이동 (`Linking.openURL`)
- 이미지는 Naver 핫링크 → `referrerPolicy="no-referrer"` 적용 (web)

---

### Step 7 — 위시리스트 (UC-02 그대로 활용)
“위시리스트에 추가” 탭 → `POST /api/v1/wishlist` → 토스트 “위시리스트에 추가되었습니다”.
홈에서 “내 위시리스트” 진입 → ACTIVE/PURCHASED 탭. 가격 합계 표시.

---

### Step 8 — 종료
지수는 위시리스트에 담은 침대를 “비슷한 실제 상품” 링크로 Naver에서 즉시 검토.
실 가구를 구매하기 전, 큐레이션 GLB를 방에 AR로 배치해본 결과가 결정에 도움됨.

## 2. 대체 시나리오 (오늘 만든 안전망이 작동하는 경로)

### 2-A. 분석 실패 분기
- AI가 `IMAGE_NOT_FOUND`를 반환하면 Backend가 `status=FAILED`로 마킹.
- Mobile AnalyzingScreen은 “분석 실패 — 다른 사진으로 다시 시도” UI 표시.
- 조치: 사용자가 “다시 업로드” 탭 → UploadScreen 회귀.

### 2-B. Naver 자격증명 부재
- 야간 배치가 시작 시 `NaverShoppingClient.isConfigured()=false` → 로그만 남기고 silent no-op.
- `/similar` 응답: `items:[]`
- Mobile 카드 하단: “준비 중” 점선 placeholder 3개로 자연 폴백 — 카드 높이 변동 없음.

### 2-C. 정적 자산 누락
- `/static/furniture/nope.jpg` 요청 → 404 (`NOT_FOUND`, 한글 메시지) + correlationId.
- (이전: catch-all이 잡아 500 STORAGE_PERSIST_FAILED 반환 → 운영자가 “서버 장애인가 파일 누락인가” 혼동.
  오늘 `NoResourceFoundException` 전용 핸들러 추가로 해소.)

### 2-D. AR GLB 미존재 / 미할당
- `RecommendationItem.modelUrl == null` → `ARPlacementScreen`이 `MODEL_URL_BY_TYPE`의 type 단위 GLB로 fallback
- 빈 placeholder GLB지만 `<model-viewer>`가 load 이벤트는 발생 → “배치 완료” 버튼은 활성, 단지 시각적으로 비어 보임.

### 2-E. WSL/Hyper-V로 인한 포트 충돌 (개발 환경 특화)
- 8080은 `wslrelay.exe`, 8081은 svchost(Host Networking Service)가 동적 점유 가능.
- Backend는 18080, Mobile은 8082로 자동 이전. `apiBaseUrl`이 `app.json`에 18080으로 박혀 있음.

## 5. 시나리오의 “성공 기준”

체크리스트로 운영 가능:

- [ ] AI 첫 cold start 후 두 번째 분석 호출이 < 3s 안에 끝남
- [ ] ObjectsScreen에서 bbox 좌표 비율(이미지 width/height 대비)이 일치 — 사진 안 가구에 박스가 정확히 그려짐
- [ ] RecommendationScreen 카드 이미지 URL이 모두 `http://localhost:18080/static/furniture/...`
- [ ] AR 화면 GLB가 load 이벤트 발생, “배치 완료” 활성
- [ ] “비슷한 실제 상품” 카드 10개 이내 / 빈 캐시 시 “준비 중” 3개 폴백
- [ ] Naver 카드 탭 → 외부 브라우저에서 정상 페이지 로드 (핫링크 차단 시 backend 프록시 단계 필요 — 후속 작업)
- [ ] `/static/furniture/nope.jpg` 요청 시 HTTP 404 (`NOT_FOUND`), 500 아님
